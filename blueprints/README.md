# Suffice — Project Blueprints

This folder is the design and engineering specification for **Suffice**, built on the
`expense-tracker` Expo base. It is written **before** the feature code, so every screen,
table, flow and decision has a single agreed source of truth.

## Documents

| File | Answers |
| --- | --- |

| [`02-data-model.md`](./02-data-model.md) | SQLite schema (DDL), money/date rules, indexes, migrations, derived metrics |

## Reading order

1. `00-vision.md` — decide *whether* a feature belongs at all.
2. `05-roadmap.md` + `08-work-phases.md` — decide *when* it belongs and what blocks it.
3. `02-data-model.md` — decide what it costs to store.
4. `03-screens.md` + `07-page-designs.md` + `04-design-system.md` — decide what it looks like.
5. `09-flows.md` — decide how it behaves end to end.
6. `01-architecture.md` + `06-decisions-and-risks.md` — decide how it is built and what can bite.

## Ground truth about the current repo

Verified from the repository, not from memory:

- Expo SDK **58** (`expo ~58.0.25`), React Native **0.88.1**, React **19.3.0**.
- `expo-router ~58.0.31` with `experiments.typedRoutes` and `experiments.reactCompiler` enabled.
- TypeScript strict, path aliases `@/*` → `src/*` and `@/assets/*` → `assets/*`.
- `src/app/` contains the implemented P0–P6 route tree: onboarding, tabs, add/detail, settings
  stack and a `__DEV__`-only data screen. Logic lives in `src/features` and `src/lib`.
- `app.json` sets the user-facing name **Suffice**, `scheme: "expensetracker"`,
  `userInterfaceStyle: "automatic"`, splash background `#121317`, bundle/package
  `com.suffice.money` and `web.output: "server"`.
- `ios/` and `android/` are **not** committed — they are generated by CNG. Never hand-edit them;
  configure native behavior in `app.json` and config plugins.
- Already installed and usable for native-feeling UI: `@expo/ui`, `expo-glass-effect`,
  `expo-symbols`, `expo-image`, `expo-font`, `react-native-reanimated`,
  `react-native-gesture-handler`.
- Typeface is **Geist** (variable, OFL) at `assets/fonts/Geist-Variable.ttf`; the mockups embed
  the same file, so design and implementation share one font.

## Rules for keeping the blueprints honest

- Change the blueprint in the same commit as the code it describes.
- Any decision that is expensive to reverse gets an ADR in `06-decisions-and-risks.md`.
- Anything not in `00-vision.md`'s scope or `05-roadmap.md` is not built, even if it is easy.
- A flow in `09-flows.md` and the code must agree; if they don't, one of them is a bug.
- Mockups in `designs/` are generated from the tokens in `04-design-system.md` — never edit a
  PNG, regenerate it.
- Before writing code against an Expo API, re-read the SDK 58 page
  (`https://docs.expo.dev/versions/v58.0.0/...`) — Expo renames and moves APIs between SDKs.
