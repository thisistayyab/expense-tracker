# Designs

Rendered page mockups for the expense tracker — light **and** dark. These are **design references
for implementation**, not screenshots of the app.

```
designs/
  build.mjs                 generates every screen from one set of design tokens
  mockups/screens/*.html    one browsable page per screen, per theme
  mockups/png/*.png         390 × 844 at 2× DPR — light and dark
  mockups/index.html        light contact sheet        (open this in a browser)
  mockups/index-dark.html   dark contact sheet
  design-board.png          light overview (3 × 4)
  design-board-dark.png     dark overview (3 × 3)
  ../../assets/fonts/       Geist variable + OFL licence (shared with the app)
```

All of the HTML is generated by `build.mjs` and kept alongside the PNGs so the mockups are
browsable without any build step. If a screen 404s, run `node blueprints/designs/build.mjs` to
regenerate the set — that is the only way these files disappear.

## Regenerate

```bash
node blueprints/designs/build.mjs
```

Then render every HTML to PNG with headless Chrome:

```bash
CHROME="/c/Program Files/Google/Chrome/Application/chrome.exe"   # macOS: /Applications/Google Chrome.app/Contents/MacOS/Google Chrome
ROOT="$(pwd -W 2>/dev/null || pwd)"

for f in blueprints/designs/mockups/screens/*.html; do
  name="$(basename "$f" .html)"
  "$CHROME" --headless=new --disable-gpu --hide-scrollbars \
    --allow-file-access-from-files --virtual-time-budget=2500 \
    --force-device-scale-factor=2 --window-size=470,920 \
    --screenshot="$ROOT/blueprints/designs/mockups/png/$name.png" \
    "file:///$ROOT/$f"
done
```

Boards (one per theme):

```bash
"$CHROME" --headless=new --disable-gpu --hide-scrollbars \
  --allow-file-access-from-files --virtual-time-budget=2500 \
  --force-device-scale-factor=1.5 --window-size=1000,2450 \
  --screenshot="$ROOT/blueprints/designs/design-board.png" \
  "file:///$ROOT/blueprints/designs/mockups/index.html"

"$CHROME" --headless=new --disable-gpu --hide-scrollbars \
  --allow-file-access-from-files --virtual-time-budget=2500 \
  --force-device-scale-factor=1.5 --window-size=1000,2450 \
  --screenshot="$ROOT/blueprints/designs/design-board-dark.png" \
  "file:///$ROOT/blueprints/designs/mockups/index-dark.html"
```

Three things that silently break rendering:

- `--screenshot` must be an **absolute** path; Chrome resolves a relative one against its own
  working directory and writes nothing on Windows.
- `--allow-file-access-from-files` is required for the `@font-face` file to load from disk. Without
  it the PNGs quietly render in the fallback face.
- `--virtual-time-budget=2500` gives the font time to load before the shot. Measured: with Geist
  loaded, `1111` and `8888` are both 99.84 px at 40 px (tabular); in the fallback they diverge.

No server is required — the generated pages are self-contained except for the shared font file.
Both `file://` and a plain static server work; over `file://` Chrome needs
`--allow-file-access-from-files` so the font loads, otherwise the page renders in the fallback
face.

## Font

Mockups and the app use the **same** `assets/fonts/Geist-Variable.ttf` (variable, 100–900, OFL).
Each page inlines an `@font-face` pointing at a relative path to that file, so the mockups and the
app can never drift onto different typefaces. Licence text lives beside the font.

## Rules

- Tokens come from `04-design-system.md`. Editing a color, size or radius in `build.mjs` without
  updating that document is a bug.
- Mockups show **populated** states, except `home-empty`, which pins the first-launch design: no
  keyboard, no keypad, no auto-presented add sheet.
- Every screen exists in both themes except `onboarding`, which is dark by design in both.
- Empty, loading and error states are specified in `07-page-designs.md` and must be designed in
  code before a screen is considered done.
- Use placeholder data only — no real names, no real card digits.
- Contrast is checked against the darkest dark and the warmest light surface, not against white.

## Screens

Light: `onboarding` · `onboarding-currency` · `home` · `home-empty` · `add` · `transactions` ·
`detail` · `budget` · `insights` · `settings`

Dark: the same list minus `onboarding`, prefixed `dark-` (`dark-home`, `dark-add`, …).

`onboarding-currency` is the country → currency step (onboarding step 2, and the same screen
reached from Settings → Country / Currency). Country markers are drawn as ISO code chips because
headless Chrome on some hosts does not render flag emoji — the app uses flag glyphs on device with
the same code chip as fallback.

`design-board.png` is a single overview image of the ten light screens (3 × 4);
`design-board-dark.png` shows the nine dark screens (3 × 3). Both are useful for review and
sharing.
